# P1 four-head end-to-end toy: hard / Laplace / MC / BPnP single-branch IFT

> **一句话结论**：在完全相同的协议（120 步、lr=0.01、clip=1.0、20 seeds）下，第四个 head——**branch-identified BPnP 单分支 IFT**——与 hard argmin 在所有实现的轨迹上数值一致或只差分支选择，而与 hard 的本质区别只在精确 tie：hard 在 $\theta=0$ 处导数不存在（两支相对差 1.87，跨 $\pm h$ 的 argmin 分支 $|q_+\cdot q_-|=4.7e-18$），而 BPnP 固定分支后有定义、且与同一 head 的中心差分吻合到 5.9e-06。**关键结论：现有 `hard` head 的反向本来就是完整 3×3 Riemannian IFT（手工重解 IFT 复现 `dposes` 到 1e-14），所以“argmin+IFT”不是一个新 head，论文不能把它和 hard 当两个 baseline 计数。**

## 0. Setup: the four heads, and what the fourth one actually is

| head | branch selection | derivative | stochastic? |
|-|-|-|-|
| `hard` | `argmin_k J_k(theta)` re-selected at **every** theta | `core.ift_dq` on the argmin branch (already a full 3×3 Riemannian IFT) | no |
| `laplace` | all enumerated minima, weights $\propto e^{-J_k/\tau}\det H_k^{-1/2}$ | analytic: $\dot w$ + $\sum_k w_k\dot\phi_k$ | no |
| `mc` | same weights, n=200 mode draws | score function $\frac1n\sum(\dot\phi_{k_i}+\phi_{k_i}s_{k_i})$ | yes |
| `bpn` | **branch id fixed once** (argmin at $\theta_0$), then tracked by $\max_k|q_k\cdot q_{\rm ref}|$; never re-selects the argmin | `core.ift_dq` on the tracked branch | no (enumeration seed fixed) |

**Why not the literal recipe.** The task asked for "enumerate once, take the hard branch, differentiate via `ift_dq`". That is *exactly* what `run_main.hard` already does: it returns `dposes[argmin J]`, and each `dposes[k]` is `core.dpose_dq @ core.ift_dq` (no detach, no straight-through). Audit (d): the literal recipe reproduces `hard` to 0.0e+00. Adding it as a fourth head would duplicate a row and let the paper count one derivative twice. We therefore make the fourth head the genuinely distinct object BPnP is -- **branch-identified** single-branch IFT -- and report the equivalence explicitly so nothing is hidden.

`bpn` fails honestly where a fixed correspondence set has no solution: if the tracked branch folds away (no mode with $|q\cdot q_{\rm ref}|\ge$ 0.75), the layer keeps its last pose with $\dot\phi=0$ and the event is counted (column `lost`). This instance *does* fold (panel E), so this is not hypothetical.

Protocol (identical to `run_e2e_fit.py`, so the three old heads are reproduced bit-for-bit): instance seed 20261127, `N_STARTS=128` cold enumeration, $\tau=0.01$, 120 steps, lr=0.01, global-norm clip 1.0, 20 initial $\theta_0\sim U[-0.2,0.2]$ drawn from `default_rng(100+s)`; $\theta$ hard-clipped to $\pm$0.5. One extra forward at the final $\theta$ defines `loss_final`.

Reproduction of `results/e2e_fit.json`: max $|\Delta$loss$|$ over every stored point of the 6 old cells = 0.0e+00, max $|\Delta\theta_{\rm final}|$ = 0.0e+00. The harness is faithful; the only new numbers are the `bpn` rows.

## 2. Gradient check: analytic dpose/dtheta vs central FD of the *same* head

- **Parameterisation.** Input: scalar theta; unit quaternion q on S^3; the IFT is solved in the 3-dim orthonormal tangent basis E(q). IFT: `dq*/dtheta = -E H^{-1} E^T (2 Jv^T dM v2), H = E^T (d^2J - 4 J I) E (3x3 Riemannian Hessian)`. Output: phi = [vec R(q) (row-major, 9); t* = GinvD v2(q) (3)] in R^12. Error: relative error = ||analytic - fd||_F / ||fd||_F on the Euclidean R^12 vector; FD perturbs theta, the pose is never differentiated numerically. The FD perturbs $\theta$ only -- no branch following, no surrogate head.
- The enumeration start set is held fixed (seed 20261127) at every $\theta$, $\theta\pm h$, so each head is a deterministic function of $\theta$ and the FD sees exactly the head's own forward map (no enumeration noise).

**hard at the exact tie.** The two one-sided branch derivatives have norms 2.7605e+01 (right) and 2.7719e+01 (left), relative difference 1.87 -- the derivative does not exist. Inside $\pm10^-3$ the argmin branch changes altogether ($|q_+\cdot q_-|=4.7e-18$), so the central difference is not just ambiguous, it is meaningless. Reported as **N/A**, as before.

**MC needs three numbers, not one.** The analytic MC gradient is a *total* derivative estimator, $\dot{\bar\phi}=\frac1n\sum_i\dot\phi_{k_i}+\frac1n\sum_i\phi_{k_i}s_{k_i}$; the two terms have different FD behaviour:

1. the **reparameterised** part $\frac1n\sum_i\dot\phi_{k_i}$ is checkable by a fixed-index central FD (hold the indices drawn at $\theta$, map them to the same modes at $\theta\pm h$ -- the J-sorted mode lists reorder across the tie, so a positional FD would compare different modes);
2. the **score** part is the derivative of the sampling *measure* and no pathwise FD can see it (the seeded forward map is piecewise constant in the draws);
3. the **total** is checked against a genuine FD of the quantity it targets, $\mathbb{E}[\phi]$ ($4\times10^6$ i.i.d. draws per side).

Reading:

- `laplace` is exact to FD truncation, but note the $\theta=0$, $h=10^{-3}$ row: the Laplace pose is so steep near the tie ($\dot\phi\sim5\times10^{2}$ with curvature over the crossing width $\tau/\text{slope}\approx1.5\times10^{-3}$) that $h=10^{-3}$ central differencing is already inside the nonlinear region. Two step sizes are reported for exactly this reason; at $h=10^{-4}$ the error drops by ~4 orders of magnitude.
- `hard`/`bpn` agree to machine precision away from the tie and `bpn` stays differentiable *through* the tie: at $\theta=0$ its analytic derivative equals the right-hand (descending-branch) value of `hard`, which the FD confirms. This is the honest statement of what BPnP buys: not a derivative where none exists, but a **branch-conditional** derivative -- finite, and equal to the one-sided derivative of the branch it tracks.
- `mc`'s total derivative passes the expectation-level FD: with the estimator's own $n=200$ noise averaged out over 20 seeds the residual is 2.4e-03 at $\theta>0$ (and 4.2e-02 at the tie, where the FD itself is truncation-limited). A pathwise FD of the sampled forward disagrees at the score-share level -- that is the score term, not an error.

**The tie is where FD becomes unreliable for everything.** At $\theta=0$ the log-weight of a mode changes by $\Delta J/\tau\approx0.66$ over $\pm10^{-3}$, so even the *smooth* Laplace/expectation maps have ~5% $h^2$ truncation error at $h=10^{-3}$ and the $h=10^{-4}$ FD is limited by its own sampling noise. The analytic derivative has neither problem; that is the practical argument for it, and the reason the two step sizes are reported side by side rather than one.

## 5. Caveats

1. **`bpn` is not a second derivative formula.** It differs from `hard` only in branch *selection*. Do not report it as an independent baseline for gradient accuracy; the only place it is genuinely different is the tie ($\theta=0$) and any trajectory where the argmin switches branch.
2. **The instance folds.** Branches annihilate at $|\theta|\approx0.12$ (panel E), so a fixed-branch head has a finite domain of validity and can end up on a saddle; `n_nonmin` counts those steps. `hard`/`laplace`/`mc` silently re-enumerate and never see the problem, which is an advantage of re-enumeration, not a bug.
3. **`bpn`'s branch id is per-seed** (argmin at $\theta_0$), so it is not the same functional as `hard` on tie seeds; the fit comparison is therefore a comparison of policies, and seed-by-seed differences at the tie are expected.
4. **MC gradient check**: the score term is only verified in expectation (4e6 draws, 1σ noise column above). A pathwise FD *cannot* verify it, by construction.
5. **FD step sizes**: $h=10^{-3}$ is too coarse near the tie for Laplace (curvature), $h=10^{-4}$ is the trustworthy row; $h$ is applied to $\theta$ only.
6. **Throughput** is CPU-only, single-thread BLAS, one process, on a shared node; absolute ms are not portable, shares are. The batch test is a loop, not a batched kernel.
7. The fit runs in 4 worker processes (the protocol is per-seed independent, so this does not change any number; it is verified against `e2e_fit.json`).
