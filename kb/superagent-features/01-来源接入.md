# 01 来源接入：请求从哪里来，谁可以发起

> **结论先行**：SuperAgent 只接收它监听的来源里的**事件**，把它们翻译成不可变的 Trigger。来源负责"哪些消息算事件、属于哪个线程、回复发到哪里"；是否构成工作请求，则由下一层的准入（Gate）和研判（Eval）决定。名单之外的人、bot 和 CI 不能授权工作。

**如果只记三件事**：

1. 内置两种来源：**GitHub**（通知、订阅的 Issue/PR、评论与 review、CI）和**飞书**（群、单聊、图片、话题）。
2. 每个来源有独立的读位置、bot 身份和允许名单；**不跨来源映射同一个人**。
3. 准入分三层：**谁发的**（名单/bot）、**在什么范围**（群/单聊/仓库范围）、**是否明确请求**（@、后续消息、准入表）。

## 0. 口径

| 概念 | 中文 | 说明 |
|-|-|-|
| Source | 来源 | 一种事件流：一种插件类型 + 一份实例配置（是否启用、监听什么） |
| Trigger | 触发 | 来源里的一条不可变事件，带来源自己的元数据（作者、消息 id 等） |
| Thread | 线程 | 按来源规则组织起来的一系列 Trigger；同一线程同一时刻只跑一个 Eval |
| Channel | 频道 | 线程的写侧：确认、回答、结果、请求决定、回执表情都通过它发出 |

## 1. 来源一：GitHub

- **入口**：代理账号的 GitHub 通知（被 @、被指派、review 请求等），以及订阅的 Issue、PR、评论、review、默认分支 CI。
- **可选"全量观察"**：`observeIssues`、`observePulls`、`observeComments`、`observeCi` 四个开关，默认关闭；打开后接收仓库里每个新 Issue、新 PR、新评论和默认分支 CI。
- **PR 生命周期**：合并或关闭会作为线程关闭事实进入系统；工单据此结束，并发出一次结果通知。
- **轮询**：默认 60 秒一轮；读位置持久化，重启不重放；单条读失败保留在线程上，连续失败达到阈值才把来源标为错误；404 会重试（可能是临时失去私有仓库权限）。
- **写回**：Issue/PR 评论、review 线程回复；消息按工单和会话保序，失败退避重试，目标消失则记为 dropped。

## 2. 来源二：飞书

- **入口**：机器人事件（@ 机器人、单聊），以及配置过的群。每个群可设"仅 @"或"全部消息"；其他群默认只接收 @；单聊可开关。
- **历史恢复**：启动后恢复配置群与已知单聊的历史，重启不丢；话题内后续消息通过轮询补读。
- **订阅话题轮询**：工单订阅的线程在工单存续期间持续轮询，并在最后一次触发/工单结束后再保留两周；之后只靠普通事件进入。
- **图片**：消息里的图片可以下载并作为附件交给研判或 worker 读取。
- **回执**：收到并准入的近期消息会加一个 `OK` 表情回执；超过新鲜窗口（约 5 分钟）就不再补。
- **写回**：在原话题内回复；支持 Markdown 转飞书富文本；消息有 100 词硬上限。

## 3. 谁可以发起：Gate

来源只回答"消息是否到达"，Gate 回答"这条消息能否成为工作"。

| 判定 | 规则 |
|-|-|
| 明确请求 `explicit` | 允许名单里的人 @ 了代理，或直接单聊；或准入表某个格子被设为"明确请求" |
| 推断候选 `inferred` | 名单外的人在有工单的线程里继续发言（默认）；准入表设为"推断候选"的格子；来源 bot 名单里的 bot 的合规消息 |
| 不准入 | 其他 bot、被准入表忽略的格子、`off` 模式下的所有推断场景 |

- **允许名单按来源独立维护**：GitHub 用 login，飞书用 open_id；同一个人在不同来源是两个身份，跨来源对应关系只写在提示词/技能里，不进入权限系统。
- **飞书群成员同步**：可以把某个群设为名单来源，启动时和点 **Sync now** 时同步成员。
- **bot 名单**：可以列出 `dependabot[bot]` 这类账号，让它们的消息成为**推断候选**；bot 永远不能发明确请求，也不能停止工单。GitHub App、`[bot]` 结尾的 login、飞书机器人会被自动识别为 bot。
- **后续消息**：线程里已有工单时，人的后续消息默认以 `explicit` 强度进入；名单外的人则是 `inferred`，除非准入表明确放开。
- **准入表**：每个接收范围（飞书群/其他群/单聊；GitHub issues/pulls/comments/ci）一行，三格分别决定"名单内未 @""名单外 @""名单外未 @"是明确、推断还是忽略。CI 没有作者，只使用最后一格。

## 4. 接单模式与主动规则

| 模式 | 行为 |
|-|-|
| `off` | 所有推断候选都不进入研判；只有明确请求能开工 |
| `observe`（默认） | 推断候选照常研判，但正面结论只记录为"would accept"，不真正接单；用来观察代理会做什么 |
| `auto` | 推断候选的正面研判可以真正接单，但必须至少命中一条启用的主动规则 |

- **主动规则**是团队写的"哪类主动工作可以做"的说明，例如"修正错别字/文案"和"有明确目标或既有标准的局部视觉修复"。每条规则有 id、名称、启用状态和 instruction；研判必须对**每条启用规则**给出匹配与否的判断。
- **规则只能收窄、不能扩大授权**：工单的 Mandate 记录命中的规则，执行器只被授权做规则范围内的局部改动。
- **Policy 版本**：规则、模式、各来源的名单/准入表/bot 名单共同构成一个版本；版本变化会丢弃进行中的 Eval、重排 Trigger，并给受影响的在途工单发"策略已变"的输入，但**不会立即撤销**已发出的 Mandate。
- **防误判**：引用/转发的文字只是数据，不能授权；主题相似不等于同一件事；视觉反馈必须给出明确目标或可验证的既有标准，否则只观察、不接单、不发确认。

## 5. 频道与可靠性

- 每条外发消息先落库（Outbox），再异步发送；失败按 5 秒起、翻倍至 300 秒退避。
- 同一工单发往同一会话的消息保序：确认在结果之前；前一条连续失败三次才显示为系统问题。
- 目标会话被删除、被锁定、消息被撤回，或来源不再监听该会话时，消息记为 **dropped**，保留时间、原因和所属工单，不再重发。
- 来源关闭时消息**等待**而不是丢弃；来源恢复后继续发。

## 6. 本机实例（2026-11-25）

| 项 | 值 |
|-|-|
| GitHub | 仓库 `ds4syk/dsh-superagent-playground`，代理账号 `ds4syk`，通知轮询 60 秒；四个"全量观察"开关关闭 |
| 飞书 | 3 个群设为"仅 @"，单聊开启，其他群"仅 @"；机器人 `Reach` |
| 模式 | `observe`：主动候选只记录，不自动接单 |
| 主动规则 | 两条启用：文案修正、局部视觉修复（需明确目标/既有标准） |
| 允许名单 | GitHub：1 人；飞书：1 人（群成员未开启同步） |

> 部署数字只代表这一套实例。换部署后以面板 **Settings** 和 `scripts/dsh-superagent status` 为准。
