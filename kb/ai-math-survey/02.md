# 02 工具与 Skill：需不需要客制化？

> **结论先行**：**看目标**。只要“探索性草稿”，通用模型 + Python 沙箱就够；要“可信交付”，
> 必须客制化：Lean/Mathlib + Comparator + 自动形式化/证明修复 + 领域工具 + 隔离编排 + 审计。
> OpenAI 的 10 个公开案例全部带 Lean 文档与 Comparator challenge，但形式化范围普遍小于论文声称，
> 这正是“需要工具、但工具还不够”的直接证据。

**如果只记三件事**：

1. 不存在“一个万能 Skill”解决所有数学证明；合理形态是“通用编排 + 领域工具包 + 验证流水线”。
2. 最小可信工具链：固定版本 Lean 项目、`sorry`/公理扫描、独立 Comparator 声明、可复现的数值脚本。
3. 工具能提高“可验证性”和“反例搜索效率”，但不能替代提出关键引理；不要把工具当想法。

## 0. 口径

| 层级 | 目标 | 最小工具 | 是否必须 |
|---|---|---|---|
| L0 探索 | 有没有思路 | 通用模型 + Python | 否 |
| L1 草稿 | 可读证明 | + 文献/检索 | 否 |
| L2 验证 | 关键步骤可检查 | + CAS/数值/SAT | 视问题 |
| L3 可信 | 机器可检验 | + Lean/Mathlib/Comparator | 是（若要求可信） |
| L4 交付 | 可审计、可复现 | + 版本化/CI/证据链 | 是（团队交付） |

## 2. 最小可信工具链（建议实现为 Skill）

### 2.1 `lean-check`：固定项目 + 内核检查

```text
输入：Lean 文件/定理名
步骤：
  1. 固定 Lean/Mathlib 版本与 lakefile；
  2. lake exe cache get（离线缓存）；
  3. lake env lean <file>；
  4. 扫描 sorry/admit/axiom/native_decide；
  5. #print axioms <theorem>，确认只依赖 propext/Classical.choice/Quot.sound；
  6. 反 vacuity：用负对照/非空实例检查定义不是空的。
输出：通过/失败 + 公理闭包 + 日志。
```

参考：本仓库此前的四色定理 Lean 4 复现（另一个分支的 `fourcolor-lean/`）就是这套流程的可运行模板；
它固定了 Lean `v4.34.0-rc2` 与 Mathlib commit，构建 821 个模块，并用 `#print axioms` 与负对照审计。

### 2.2 `autoformalize`：自然语言 → Lean 命题

```text
输入：题面（自然语言）+ 定义表
步骤：
  1. 让模型输出 Lean 命题骨架（只到 theorem 语句，不写证明）；
  2. 人工/独立模型校对量词、假设、记号；
  3. 用小实例/反例检查命题不是 vacuous；
  4. 冻结命题，再让模型填证明。
输出：冻结的 Lean 命题 + 校对记录。
```

关键：**先冻结命题，再证**。否则模型可能“证明了一个不同的命题”。

### 2.3 `proof-repair`：编译错误 → 子目标 → 修复

```text
输入：Lean 文件 + 编译器错误
步骤：
  1. 解析错误位置/目标；
  2. 生成候选 tactic/子目标；
  3. 重新编译；
  4. 失败则缩小到最小复现；
输出：修补后的文件 + 剩余 sorry 列表。
```

### 2.4 `numeric-probe`：沙箱数值/符号实验

```text
输入：Python 代码
步骤：
  1. bubblewrap/容器沙箱，无网络，CPU/内存/时间限制；
  2. 运行，保存 stdout/stderr 与随机种子；
  3. 把“计算检查了什么/没检查什么”写进证明。
输出：可复现的计算记录。
```

### 2.5 `blind-window`：信息隔离的多模型探索

```text
输入：题面（不含官方结论/解法）
步骤：
  1. 每个模型独立会话；
  2. 不给其它模型输出、不给评分 key；
  3. 记录完整 transcript 与 token/成本；
  4. 结束后由独立评分者对照官方结论。
输出：可审计的探索记录 + 评分。
```

### 2.6 `grader`：结构化评分

```text
输入：官方结论 + 候选终稿
输出：direction / main_theorem_proved / score 0-5 / fatal_gaps / evidence_quotes
```

## 3. 领域工具包

| 领域 | 工具 | 用途 |
|---|---|---|
| 数论/解析数论 | SageMath、PARI/GP、LMFDB、区间算术 | L-函数、零点、数值验证 |
| 组合/图论 | NetworkX、SAT/ILP、nauty、自定义枚举 | 反例、极值构型、有限检查 |
| PDE/分析 | 符号计算、数值 PDE、区间算术 | 渐近、爆破候选、能量估计检查 |
| 算子代数/表示论 | GAP、SageMath、线性代数 | 有限维模型、群环计算 |
| 代数几何 | Macaulay2、Singular、SageMath | 理想、簇、上同调 |
| 概率/统计物理 | 数值模拟、精确枚举 | 相变、自由能、有限尺寸 |

## 4. 什么时候不需要客制化

- 只是“看看模型有没有想法”的 pilot；
- 题目是标准竞赛题/教材题，且只需要草稿；
- 没有可信交付要求，且有人工专家兜底；
- 时间/预算极紧，先做“能否复现”的下界测试。

## 5. 什么时候必须客制化

- 要把结果写进论文/报告，且声称“证明”；
- 结果依赖大量有限计算/反例搜索；
- 需要跨模型/跨窗口独立复现；
- 需要防止“证明了一个不同命题”或“把猜想当定理”；
- 需要长期维护/CI/版本化。
