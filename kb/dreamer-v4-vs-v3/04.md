# 04 实验、规模与代价：迁移清单与局限

> **结论先行**：V4 的数字很亮眼（首个纯离线钻石、14/16 人类交互任务、单 H100 21 FPS），但它和 V3 不是同一套实验设置，也不是同算力对比。能直接带走的是“想象训练 + λ-return + symexp twohot”这套骨架；必须重做的是世界模型、数据管线、策略目标和算力预算。

**如果只记三件事**：

1. V3 的成绩是“200M 参数、单卡 A100、150+ 任务、在线首钻”；V4 的成绩是“2B 参数、256–1024 TPU-v5p、Minecraft 离线首钻 0.7%”。
2. V4 的对比对象主要是 VPT、BC、VLA、Oasis/Lucid 等，不是 V3 的 150+ 任务；不能据此说 V4 全面替代 V3。
3. 迁移时先换“世界模型 + 数据”，再换“策略目标”；直接套 PMPO 到 V3 的小 RSSM 上，收益没有论文里那么大。

| 项 | DreamerV3 | DreamerV4 |

| 训练硬件 | 1×NVIDIA A100 | 256–1024×TPU-v5p，batch size 1/device，FSDP |
| 训练数据 | 在线交互，Minecraft 约 1.4K 小时 | 离线 VPT，2541 小时 |
| 环境步数 | 100M | 0（学习阶段不交互） |
| 输入 | 64×64×3 图像 + 库存/装备/生命等向量 | 360×640×3 图像（仅像素） |
| 动作 | MineRL 扁平 categorical + 抽象合成 | 23 个按键二值 + 121 类鼠标；合成走 UI |
| Episode | 36,000 步 / 30 分钟 | 60 分钟 |
| 并行环境 | 64 | 0 |
| 训练时长 | Minecraft 8.9 GPU 天 | 论文未报告 |
| 世界模型推理 | 单步 GRU | 每帧 4 步；单 H100 21 FPS |
| 上下文 | 循环状态隐式携带 | 192 帧 / 9.6 秒 |

## 2. 结果对照

| 指标 | DreamerV3 | DreamerV4 |
|-|-|-|
| 主基准 | 8 域 150+ 任务，固定超参 | Minecraft 离线钻石、人类交互、机器人/厨房视频 |
| Minecraft 钻石 | 首个从零在线拿到；所有训练 agent 在 100M 步内拿到 | 首个纯离线拿到；1000 episodes 中 0.7% |
| 关键里程碑 | 论文报告 return 9.1（100M 步） | 石镐 90.1%、铁镐 29.0%、钻石 0.7% |
| 对比基线 | PPO/IMPALA/Rainbow 等 | VPT、BC、VLA (Gemma 3)、Oasis、Lucid、MineWorld |
| 数据效率 | 1.4K 小时在线 | 比 VPT 少 100× 数据；2.5K 小时离线 |
| 人类交互 | 未报告 | 14/16 任务成功；Oasis large 5/16 |
| 生成质量 | 未报告视频 FVD | FVD 57；朴素 diffusion forcing 306；v-space 124 |
| 动作泛化 | 未报告 | 10 小时动作 → 53% PSNR / 75% SSIM；100 小时 → 85% / 100%；OOD 76% / 80% |
| 实时性 | 单步，天然快 | 单 H100 21 FPS，9.6 秒上下文 |

## 3. 不能直接比较的地方

1. **动作空间不同**：V3 用 MineRL 的抽象合成动作，V4 用原始鼠标键盘、合成要在 UI 里点。V4 的控制难度更高，但动作序列也更长（钻石约 20,000+ 步）。
2. **观测不同**：V3 有库存/装备/生命等向量，V4 只有像素；V4 不能靠“读库存”走捷径。
3. **数据不同**：V3 的数据是自己在线采的，分布随策略变化；V4 是固定的人类视频数据，分布更广但不可交互纠错。
4. **算力不同**：200M/1×A100 对 2B/256–1024 TPU-v5p，不是同预算对比；V4 的“更好”很大一部分来自规模。
5. **评测范围不同**：V3 证明的是“跨 150+ 任务一套超参”；V4 证明的是“复杂视频世界里离线学行为”。两者回答的问题不同。

## 4. 迁移清单：从 V3 到 V4 要改什么

| 类别 | 内容 | 建议 |
|-|-|-|
| 直接保留 | imagination training、λ-return、γ=0.997、symexp twohot reward/value、测试时不 planning | 先在 V3 代码里确认这些部件的语义，迁到 V4 时不要改坏 |
| 必须替换 | RSSM/GRU/CNN → causal tokenizer + block-causal transformer；KL/重建 → shortcut forcing；单步 prior → 4 步采样 | 这是工作量最大的部分，先做小分辨率原型 |
| 必须新增 | 离线数据管线（视频 + 动作 + 事件标注）、task embedding、BC 阶段、reward model 的 MTP、PMPO、value head | 按 Algorithm 1 的三阶段拆分，不要一步到位 |
| 可以删除/降级 | return normalization、entropy 正则、continue 预测头（推断：V4 论文未描述）、在线 replay/环境循环（离线设定下） | 先保留开关做消融，确认没有隐性依赖 |
| 算力 | 2B 模型、256–1024 TPU-v5p、长上下文训练 | 没有同等级算力时，先做 64×64/16 帧的小规模验证，不要直接追论文数字 |

### 一条建议的最小验证路线（非论文步骤）

1. **Tokenizer**：在 64×64、16 帧的小数据上训 causal tokenizer（MSE + LPIPS + MAE），看重建 PSNR/SSIM 和逐帧解码是否正常。
2. **Dynamics**：在 token 空间训 diffusion forcing，先不做 shortcut；确认 16 帧 rollout 不崩，再换 shortcut、x-prediction、ramp weight，测 4 步采样的 FVD/PSNR。
3. **动作条件**：只给 10% 的视频动作标签，测有/无动作条件的生成差异；再测未见场景的泛化。
4. **BC + reward**：加 agent token、task embedding、MTP；先在真实环境评估 BC 成功率，确认 reward head 能区分成功/失败。
5. **PMPO**：冻结 transformer，只训 policy/value；与 BC 基线比成功率和到达里程碑的时间，确认 RL 不是“越训越差”。

每一步都应记录“论文声称 vs 本机复现”的差距；不要把论文的 2B 数字当成小规模实验的预期。

## 5. 局限与未验证

- **论文版本**：V4 目前是 arXiv v1（2025-09-29），没有 v2、没有官方代码；本知识库的所有 V4 结构描述都可能随版本变化。
- **无独立复现**：V4 的 0.7%、21 FPS、FVD 57 等数字均为论文声称；本仓库没有跑过 V4。
- **未覆盖 V3 的全 benchmark**：V4 没有重跑 Atari/ProcGen/DMLab/DMC 等 150+ 任务，不能推断“全面优于 V3”。
- **世界模型仍不完美**：论文自己承认上下文只有 9.6 秒、库存预测不精确、不是完整游戏克隆；长程记忆和精确物品状态仍是问题。
- **算力门槛**：2B + 256–1024 TPU-v5p 的训练预算对多数实验室不可行；论文没有给出 wall-clock 和总 GPU/TPU 小时。
- **数据与动作标签**：V4 的“无动作视频预训练”仍需要少量动作数据做 grounding；动作标签的对齐质量会影响结果。
- **推断项**：V4 没有 continue 预测头、没有 unimix 等结论，是由论文结构与损失“未出现”推断的，不是作者明说；迁移时需以实际代码/消融为准。
