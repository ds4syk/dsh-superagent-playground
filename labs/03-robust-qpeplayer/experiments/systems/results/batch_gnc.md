## 6. 限制与备注

1. 单节点共享服务器（Slurm `cpu` 分区），wall-clock 计时含系统噪声；p95 尤其，绝对 ms 会随负载漂移，加速比的结论以 p50 为主、p95 作参考。
2. 批量实现是**逐位复刻**循环的调度：每个实例用自己的 μ0 与迭代次数，结束的实例从 active 集合移除、不重算；因此 n_mu 与循环完全一致（表 §3、§4 最后一列）。
3. `eigh` 后端用 Horn/Davenport 四元数法替代 3×3 SVD，二者给出同一最优旋转；`svd` 后端在 §3 中逐实例对比，差 < 1e-14。若要求与循环**同一 LAPACK 路径**，可用 `batch_solve_gnc(..., method="svd")`。
4. 吞吐 = B / 整批延迟，按同一 cell 的 p50 计算；不是 GPU 饱和吞吐，B=128 仍然远小于可并行的实例数。
5. 本实验只测工程吞吐；不改变 theory/verify 或既有实验结论，外点生成、c、μ 调度与 `synthetic/common.py` 完全一致。
6. GPU 侧是 eager torch、float64、每条 python 循环逐迭代触发 kernel；在 B<=128 时 launch 开销主导，GPU 地板约 40 ms。CUDA graph / torch.compile 融合、float32、更大 B 均未做（超出本轮范围）。因此本报告不建议用 GPU 替代 CPU 批量实现，除非 batch 更大或做了融合。
