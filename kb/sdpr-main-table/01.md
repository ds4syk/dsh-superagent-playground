# 01 数据集选择与评测协议

> **结论先行**：主数据集选 **SPEED+**（HIL 双域 + 官方 `Epose`），第二数据集只用来回答一个明确问题——跨域泛化、真实飞行 sanity check、事件/光照鲁棒，或层改进的受控对照。训练/验证/测试三划分固定，所有方法共用；只报 HIL 验证不算完成主表。

## 如果只记三件事

1. **SPEED+ 是 spacecraft 主线的唯一主数据集**：synthetic 训练 + lightbox/sunlamp 两个 HIL 域评测，官方指标 `ET`(m)、`ER`(°)、`Epose`。
2. **第二数据集按“要回答的问题”选**：泛化 → SPEED；真实域 → prisma25；光照/事件 → SPADES；层改进对照 → In-The-Dark / BAL / Replica。
3. **公平性靠协议而不是口号**：同训练数据、同 split、同输入分辨率、同是否 crop、同是否用 HIL 标签；test 只走官方 leaderboard，不在 val 上调参。

## 0. 口径

- SPEED+ 组成与指标来自 Park et al., *SPEED+*, IEEE Aerospace 2022（arXiv:2110.03101）。
- SPNv2 的训练/评测协议来自 Park & D'Amico, *Robust multi-task learning…*, Advances in Space Research 2023（arXiv:2203.04275）。
- 你当前草稿的划分与数字来自上传的 `E2E_pose_est_v1.pdf`（2026-11-02 稿），属于“论文草稿”，不是已发表口径。

## 1. 主数据集：SPEED+

| 项目 | 数值/说明 |
|-|-|
| 目标 | Tango 卫星（PRISMA 任务） |
| 域 | synthetic（OpenGL 光学模拟器）、lightbox（地球反照）、sunlamp（太阳直射） |
| synthetic 划分 | train 47,966 / val 11,994（官方 80:20） |
| HIL 总量 | lightbox 6,740；sunlamp 2,791 |
| 你的草稿划分 | 训练 38,120 = 30,496 synthetic + 5,392 lightbox + 2,232 sunlamp（4:1）；验证 1,348 lightbox + 559 sunlamp |
| 官方指标 | `ET = ||t̂ − t||₂` (m)；`ER = 2 arccos|<q̂,q>|` (°)；`Epose = ER + ET/||t||` |
| SPEC2021 修正 | `Epose*`：当 `ER < 0.169°` 且 `ET/||t|| < 2.173 mm/m` 时记 0 |

**为什么是它**：公开、有标签、有官方 leaderboard、有 HIL 域差、有大量已发表 baseline。对“基于 SDPR 的新方法”，它同时提供**域差鲁棒性**（sunlamp 的强方向光）与**深度/尺度**（`ET` 以米计）两个可讲的故事。

**必须说清的三件事**：

1. **是否使用 HIL 标签训练**。你的 4:1 混合用了 5,392 + 2,232 张 HIL 图。如果这些图带标签，这是 transductive 设定，必须在表注和实验节明确；纯 inductive 方法（只用 synthetic 训练）要另给一行，不能混在一张表里假装同设定。
2. **是否 crop**。KRN 一类方法用 perfect bounding box 预裁剪；你的方法是全图输入。主表要统一“无 crop”，或在表注写明“† 使用 perfect bbox”，否则精度不可比。
3. **验证集是否参与调参**。HIL val（1,348/559）用于早停/选模后，就不能再声称它是无偏测试；最终数字应走官方 test/leaderboard，或明确标注“val only”。

## 2. 第二数据集：按问题选一个，不要堆

| 数据集 | 任务/模态 | 规模 | 能回答的问题 | 代价/风险 |
|-|-|-|-|-|
| **SPEED**（2019） | 单目 spacecraft，synthetic + ~300 real | train 12,000 / val 2,998 / test | 跨数据集泛化、小样本 | 目标与光照分布不同，掉点很正常；只作辅助表 |
| **prisma25** | 真实飞行图像 | 25 张 | 真实域 sanity check | 样本太少，只能定性或小表，不能支撑统计结论 |
| **SPADES** | 事件相机 spacecraft | 事件流 + 标签 | 光照鲁棒/事件模态 | 需要事件前端，不能与 RGB 方法直接同表；适合作为“第二模态”扩展 |
| **SLABPose**（2025） | 大规模物理合成 | 见 arXiv:2506.12782 | 第二合成集、预训练/泛化 | 新数据集，社区接受度待观察；审稿人可能不熟 |
| **In-The-Dark** | 双目相对定位（SDPR 原实验） | 100k 训练 / 20k 验证 | 层改进的受控对照 | 不是 spacecraft；指标是纵向/横向/航向误差 |
| **BAL / Replica** | SfM / 位姿图 | 多规模 | 可扩展性、全局最优性 | 指标是 ATE/RPE，不是 `Epose` |

**选择判据**：第二数据集必须让主表多回答一个**审稿人会问的问题**。如果它只是“再刷一个数据集”，不如把篇幅留给消融与证书表。

## 3. 评测协议（可直接照抄）

### 3.1 数据与预处理

- 输入统一 resize 到 **768×512**（你草稿的设置），不 crop；相机内参按同一比例缩放，使用 pinhole、不带畸变。
- 训练增强：所有方法用同一套，或都不用；SPNv2 的 release 自带增强，复现时按其推荐并记录。
- 随机种子：至少 3 个，报 mean ± std；主表不要只报单次最好结果。

### 3.2 指标与聚合

| 指标 | 单位 | 聚合 | 回答什么 |
|-|-|-|-|
| `ET` | m | mean ± std、RMSE、max | 绝对平移精度（与 SOTA 可比） |
| `ER` | ° | mean ± std、RMSE、max、P90/P95/P99 | 旋转精度与尾部 |
| `Epose` | – | mean ± std | 官方综合分（SPEED score） |
| `fail>30°` / `fail>90°` | % | 比例 | 灾难性失败/flip |
| tight rate | % | rank-1 比例或 `λ₂/λ₁ < 1e-5` | 松弛是否紧 |
| certificate rate | % | 对偶证书通过比例 | “可认证”的实际覆盖率 |
| solver time | ms | median / P95 | 可认证性的代价 |
| FPS / params | – | 端到端 | 工程可用性 |

### 3.3 防泄漏与公平性清单

- [ ] 训练/验证/测试三划分固定并公开（至少给文件列表或 split 脚本）。
- [ ] 所有方法在同一训练集上训练；若某方法必须用额外数据（ImageNet 预训练、HIL 无标签），在表注写明。
- [ ] 不在 HIL val 上反复调参后仍称其为 test。
- [ ] 不用 GT pose 做 crop/ROI；若用，单独标注。
- [ ] 同一输入分辨率与同一评测脚本；报告评测代码/提交。
- [ ] 官方 test 结果以 leaderboard 截图或提交记录为准，不只报本地 val。

## 4. 常见坑

1. **只报相对平移**。你的表用 `ET/||t||`，而 SPEED+/SPNv2 表用 `ET`(m)。审稿人无法直接比较，也会怀疑尺度误差被归一化掩盖。**两张都给**。
2. **HIL 标签设定不透明**。用了 HIL 训练却与纯 synthetic 方法同表，是典型的设定混淆。
3. **验证集当测试集**。HIL val 只有 1,907 张，调参后容易过拟合；最终必须上官方 test 或明确标注。
4. **忽略域差**。sunlamp 的强方向光才是这个 benchmark 的难点；只报 lightbox 会被认为避重就轻。
5. **忽略失败样本**。`Epose` 的均值会被大量好样本主导；不报 RMSE/max/失败率，就看不出可认证方法真正的价值（尾部）。
