# 02 决策与实施

> **结论先行**：方案只留两个点需要你拍板——**表情图案**和**回执范围**。其余按推荐默认执行；如果两个都按推荐，回复"同意"即可开始实施。

**如果只记三件事**：

1. 推荐固定 `OK`（👌），不加设置；只对"会被处理"的消息回执（人 + 监听 + 准入 + 指向/工单线程 + 5 分钟内）。
2. 文字回执保留，表情只负责"收到"；5 分钟时效窗防止历史补收刷屏；v1 只做飞书。
3. 实施约 0.5–1 天：改代码 + 测试 + 重启 + 现场验收；可回滚。

## 1. 需要你拍板的点

### 1.1 表情图案

| 选项 | 飞书表情 | 语义 | 风险 | 推荐 |
|-|-|-|-|-|
| **`OK`（👌）** | OK | "收到 / 好的" | 最通用；不表示"正在做" | ✅ 推荐 |
| `OnIt` | OnIt | "马上处理" | 比"收到"更强，可能被理解为已开工 | |
| `THUMBSUP`（👍） | THUMBSUP | "赞 / 收到" | 偏点赞，不像回执 | |
| `EYES`（👀） | EYES | "在看" | 偏"正在看"，不是"收到" | |
| 可配置 | 设置页选择 | 灵活 | 增加设置项，违背"少设置"原则 | v2 再议 |

建议：**固定 `OK`，不加设置**。要换只改一个常量，成本极低。

### 1.2 回执范围

| 选项 | 规则 | 优点 | 缺点 | 推荐 |
|-|-|-|-|-|
| **只回执"会被处理"的消息** | 人 + 已监听 + 通过准入 + 被指向或工单线程 + 5 分钟内 | 安静；不给白名单外的人错误信号 | 白名单外的人看到的是沉默 | ✅ 推荐 |
| 所有 @ 机器人的消息 | 不看准入 | 谁 @ 都有反馈 | 白名单外的人以为会被处理，可能鼓励无效 @ | |
| 所有监听消息 | 连闲聊也回执 | 规则最简单 | 群聊刷屏，违背"少打扰" | |

建议：**只回执会被处理的消息**。

### 1.3 其他默认（无异议按此实施）

| 项 | 默认 | 备选 / 备注 |
|-|-|-|
| 文字回执 | 保留 | 只留表情会更安静，但用户不知道"要做什么" |
| 时效窗 | 5 分钟 | 只对实时事件（更精确，实现更复杂）；不限时（可能刷历史） |
| 平台 | 飞书 v1 | GitHub 后续按同一接口扩展 |
| 暂停 | 跟随全局暂停 | 暂停也回执（不推荐：暂停 = 不响应） |
| 配置 | 无设置项 | 加 source 开关/图案字段（增加维护成本） |

## 2. 推荐方案（若无异议）

> 只对"会被处理"的人类消息，在入库后立即加 👌；文字回执与现有规则不变；出站队列保证幂等与重试；v1 只做飞书、不加设置。

## 3. 实施步骤与工作量

| 步骤 | 内容 | 预计 |
|-|-|-|
| 1 | 改代码 + 单元测试 | 2–4h |
| 2 | `pnpm check` + build | 20min |
| 3 | 重启 profile + 现场验收（@ / 私聊 / 工单线程 / 暂停 / 补收） | 1h |
| 4 | 文档更新（001 / 007 / 006） | 30min |
| 合计 | | **0.5–1 天** |

不新增依赖；不改 DSH 本体；只动 superagent 源码与测试。

## 4. 验收清单（上线前逐项打勾）

- [ ] 配置群里 @Reach：1–2 秒内原消息出现 👌，随后文字回执照旧。
- [ ] 私聊：同上。
- [ ] 工单线程里不 @ 的回复：出现 👌。
- [ ] 白名单外的人 @：无 👌、无文字回执。
- [ ] 未配置群 / 机器人消息：无回执。
- [ ] 重启、断线补收：旧消息不出现 👌。
- [ ] 暂停期间无 👌；恢复后旧消息不补发。
- [ ] 撤回消息：无异常，health 正常。
- [ ] 面板 health 的 `receipt` 与 `feishu` / `reply` 分开显示。
- [ ] `pnpm check` 全绿。

## 5. 回滚

1. 恢复改动前快照的源文件。
2. `pnpm build`。
3. 重启 profile `superagent`。
4. 不需要数据迁移；残留的 `receipt` effect 会在下次启动时按 gone/过期丢弃。

影响面：只重启 superagent；进行中的工单按现有 assignment 恢复机制续跑。
