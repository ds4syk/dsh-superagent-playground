# 路线图：4 / 8 / 12 周

> 起点：2026-11-27（本文档创建日）。**所有投稿 deadline 都是按历年周期的假设，必须在动手前到官网核实**——不要用本文件的日期安排提交。
> 目标：把当前"定理 + 协议 + 合成验证"推进到"可投稿 draft + 主实验"。

---

## 0. 投稿目标与理由

| 优先级 | venue | 假设 deadline | 理由 | 风险 |
|---|---|---|---|---|
| **首选** | **RSS 2027** | 2027-01 下旬（待核） | 单轨、4–6 页、重"新问题+清晰方法+真机/真数据"；本文的"物理约束进感知层"正是 RSS 的口味；不要求大规模 SOTA 刷榜，容许理论贡献 | 时间最紧；RSS 审稿对"只有合成实验"零容忍 |
| 备选 1 | **IROS 2027** | 2027-03 上旬（待核） | 6 页、容错高、审稿快；适合"方法 + T1 主表" | 影响力低于 RSS；若 12 周计划延后，这是最稳的落点 |
| 备选 2 | **RA-L（rolling）** | 随时 | 无固定 deadline，适合"先投再补"；对理论+系统都友好 | 审稿周期不可控（2–4 个月），可能拖过毕业节点 |
| 备选 3 | **NeurIPS 2027** | 2027-05 中旬（待核） | 若把叙事转向"非凸约束优化的可微层 + 广义导数理论"，NeurIPS 更认这套；本文的 Theorem 2.3 / Prop 2.1 / Example 2.5 够硬 | 需要砍掉大部分机器人实验，换成优化 benchmark；与"三篇论文"的机器人主线偏离 |
| 兜底 | **ICRA 2028** | 2027-09 中旬（待核） | 周期最长，可容纳完整 T1+T2+T3 | 太晚；仅在前面全失败时启用 |

**决策**：主攻 **RSS 2027**（8 周冲刺），若第 8 周 gate 未过则平滑切到 **IROS 2027**（12 周），不切 NeurIPS（除非理论线单独成文）。

**为什么不选 T-RO**：T-RO 周期 12–18 个月，且要求完整实验矩阵（T1+T2+T3+全部消融）；本线的时间预算不支持，且"三篇论文"的整体节奏需要更快的产出。

## 1. 4 周（2026-11-27 → 2026-12-25）：把数学钉死

**目标**：所有 P0 数学问题关闭或明确降级；前向原型跑通（合成数据）；反向 gradcheck 通过。

| 周 | 交付 | 验收标准 |
|---|---|---|
| W1 | **Q1 根数统计**：sympy 数商环维数 + 200 组随机实例的实根数统计 | 得到内层通用根数的上界；能回答"是否 40" |
| W1 | **Q2 多约束 kink 推广**：$m$ 个同时弱活跃约束的 FB 极限 | 能写出"FB 选出的权重规则"（中点？加权？） |
| W2 | **前向原型**（NumPy）：ALM + 多起点内层（先不接 QPEP） | `verify` 的 C1–C6 扩展成 50 个随机实例全部可行 |
| W2 | **Q3 决策落地**：GN 版实现 + 精确 Hessian 版对照 | 两者在 20 个实例上的梯度差有数字 |
| W3 | **反向原型**（NumPy）：FB 约化 + 鞍点求解 + gradcheck | 与中心差分相对误差 $<10^{-6}$（强活跃/弱活跃/秩亏三类分别报） |
| W3 | **Q6 非刚体单侧导数**：参数化 QP + 单侧差分 vs FB 极限 | 给出"是否等于丢掉最小乘子后的解"的结论 |
| W4 | **PyTorch 层封装**：`torch.autograd.Function` + 批处理 | 一个 batch 的前向/反向跑通；GPU/CPU 都能跑 |
| W4 | **论文 §3–§4 定稿**（英文） | 定理陈述、假设、证明草图与 `theory/proofs.md` 一致 |

**Gate G-A（第 4 周末）**：Q1 有答案（哪怕是"根数 > 40，需重生成模板"）、gradcheck 通过、论文理论部分自洽。**未过则**：把论文定位从"certifiable + 可复用 QPEP"降为"ALM+FB 的约束层 + sound bound"，仍可投 IROS。

## 2. 8 周（→ 2027-01-22）：主实验 + RSS 投稿

**目标**：T1 主表出数；证书紧率有统计；RSS draft 完整。

| 周 | 交付 | 验收标准 |
|---|---|---|
| W5 | **QPEP 求解器接入**（C++/PyBind 或纯 Python 模板） | 单样本前向 $<20$ ms（CPU）；与多起点解一致率 $>99\%$ |
| W5 | **T1 数据管线**：YCB-V 支撑平面 + 凸包顶点 + 约束构造 | 可视化 10 帧，人工确认约束正确 |
| W6 | **T1 训练**：Ours vs B1(SDPRLayers) vs B3(Theseus) vs B5(QPEP+投影) | 三张表：ADD(-S)、穿透深度/比例、延迟 |
| W6 | **证书紧率统计**（T1 全 test） | 报 tight/loose/failed 三类的比例与 $\lambda_2/\lambda_1$ 分布 |
| W7 | **消融 A1/A2/A4/A5** | 四条曲线；A4（枚举 vs 多起点）必须有显著差异，否则削弱 C1 |
| W7 | **B2（slack 版）对比** | $p=8/16/64$ 的 $(10+p)$ SDP 耗时与 tightness；这是 Q-D 的弹药 |
| W8 | **RSS draft 完整版**（含图）+ 内部 review | 8 页内；所有数字标证据级别；TODO 清零或明确标"camera-ready 补" |
| W8 | **代码/数据 release 准备** | 一键复现脚本 + README + 许可证 |

**Gate G-B（第 8 周末，RSS 投稿决策）**：
- 必要条件：(i) T1 上 ADD(-S) 不劣于 B1 超过 10%（不能为了约束牺牲太多精度）；(ii) 穿透 $<1$ mm 的帧占比 $>90\%$；(iii) 证书紧率 $>50\%$。
- 若 (i) 不满足：论文叙事改为"约束的代价与收益"，仍可投。
- 若 (iii) 不满足：标题去掉 "certifiable"，改为 "with a sound suboptimality bound"，投 IROS。
- 若 (ii) 不满足：说明实现有 bug（约束没生效），回 W5。
