# 03 机制与边界：JEV 凭什么能当世界模型，又会在哪里坏掉

> **结论先行**：JEV 能当世界模型，但只在「状态可拆成有限个变量、每个变量的取值可枚举、转移规则能从文本读出来」的窄条件下成立。它本质上是一个**因子化转移分类器**，不是生成式模拟器；把它当动作来源时，必须外接一个规划器或策略头，不能指望它自己「想出」动作。

**如果只记三件事**：

1. 世界模型的严格定义是「给定状态和动作，预测下一状态/观测」；JEV 只能预测你预先写进选项的那些变量，预测不了新物体、连续量和高维观测。
2. 动作生成有三条路：直接 choice（1 次/步）、逐动作打分（|A| 次/步）、世界模型前瞻（|A|×Q 次/步）。成本和效果依次上升，但都不是免费的。
3. 误差主要来自「命令是否执行」这类需要推导的判断；一步错会沿 rollout 累积，必须靠重规划/置信度升级/小模型蒸馏兜底。

## 0. 口径

| 概念 | 本报告的定义 |
|-|-|
| 世界模型 | 给定状态 \(s_t\) 与动作 \(a_t\)，预测 \(s_{t+1}\)（或观测 \(o_{t+1}\)、奖励 \(r_t\)）的模型 |
| 因子化状态 | \(s = (v_1,\dots,v_n)\)，每个 \(v_i\) 取值于有限集合 \(V_i\) |
| 决策模型 | 输入 state + typed question，输出选项上的概率分布，不生成文本 |
| 动作生成 | 从候选动作中选一个（或 top-k），不要求预测未来 |

---

## 1. 把「世界模型」拆成可回答的选择题

设状态有 \(n\) 个变量，动作集 \(A\) 有限。对每个 \((s,a)\) 和每个变量 \(v_i\)，问：

\[
p(v_i' \mid s, a) = \text{JEV}(\text{state}=s,\ \text{question}=\text{“执行 } a \text{ 后 } v_i \text{ 是什么？”},\ \text{options}=V_i)
\]

再加一个「命令是否执行」的二值问题。把所有 argmax 拼起来，就得到 \(\hat s_{t+1}\)。多步预测就是把 \(\hat s_{t+1}\) 当输入再问一遍。

这就是 KIIS 2026 的做法，也是本报告 Exp1 的做法。它的成立条件很明确：

1. **变量可枚举**：房间、位置、开/关/锁、持有物——这些都是有限集合。像素、关节角、自由文本观测不满足。
2. **值可从文本读出**：状态描述里必须写清楚「钥匙在箱子里」「门是锁的」。如果信息藏在图像或需要探索，JEV 无从判断。
3. **规则简单且确定**：开箱→箱子开；取钥匙→钥匙进背包。规则越接近「读约束」而不是「算物理」，JEV 越可靠。
4. **选项覆盖真值**：真值必须在你给的选项里；否则模型只能选最近的错误项。KIIS 把所有类型合法的值都列进选项，就是为了保证 support。

> 一句话：**JEV 的世界模型能力 = 你的状态因子化能力 + 你的选项设计能力**。这不是模型架构自动给你的。

## 2. 动作生成的三条路

### 2.1 直接 choice

\[
a^* = \arg\max_{a \in A} \text{JEV}(\text{“下一步该执行哪个命令？”})
\]

成本：每步 1 次决策。优点：便宜、直接。缺点：没有显式预测后果，模型只能靠先验/常识选；动作集大时（>10–20）准确率下降，REFLEX 也报告了动作集大小的影响[13]。

### 2.2 逐动作打分

对每个候选动作问「执行它是否会推进目标？」（noul）或「执行后离目标多近？」（score），取最高分。

成本：每步 \(|A|\) 次决策。优点：比直接 choice 更细，能表达「这个动作没用」；缺点：仍然是单步启发式，不会组合多步。

### 2.3 世界模型前瞻

对每个候选动作预测下一状态（\(Q\) 个问题），用效用函数打分，取最高；也可以向前展开 2–3 步。

成本：每步 \(|A| \times Q\) 次决策。以 9 个动作、8 个问题为例，72 次/步；20 步就是 1,440 次/回合。优点：真正用上了世界模型；缺点：贵，且预测误差会直接变成错误动作。

**三者的关系**：choice 是「策略」，score 是「价值函数」，lookahead 是「模型预测控制」。JEV 本身只是一个概率读出器，三种用法都需要外面包一层。

## 3. 成本模型：什么时候真的便宜

### 3.1 JEV API

单次决策的输入大约是「state + 问题 + 选项」，按 150–300 tokens 估。JEV 输入 $0.042/MTok、输出免费[1]：

\[
\text{cost per decision} \approx \frac{200 \times 0.042}{10^6} \approx 8.4\times10^{-6}\ \text{USD}
\]

- 直接 choice：1 次/步 → 约 $0.000008/步；20 步约 $0.00017/回合。
- 世界模型前瞻：72 次/步 → 约 $0.0006/步；20 步约 **$0.012/回合**。这和 KIIS 报告的 $0.010/回合（129 请求）同一量级[8]。
- 逐动作打分：9 次/步 → 约 $0.000075/步；20 步约 $0.0015/回合。

所以「JEV 很便宜」要看你问多少问题。**世界模型前瞻不是免费的**：它把单次判断的便宜，乘上了动作数 × 变量数。

### 3.2 生成式 LLM 对照

生成式模型要输出一段状态文本（约 100–300 tokens），输入 300–600 tokens。按主流 API $0.2–$10/MTok 输入、输出约 5× 计算：

\[
\text{cost per transition} \approx 0.0001\text{–}0.01\ \text{USD}
\]

比 JEV 的世界模型前瞻贵 1–2 个数量级；延迟 3–329s vs 70–500ms[1]。但生成式模型能表达开放状态，这是 JEV 做不到的。

### 3.3 蒸馏之后

如果 JEV 只用来**打标签**，成本是一次性的：

- 2,000 个状态 × 8 个问题 × 200 tokens × $0.042/MTok ≈ **$0.13**；
- 训练一个 1M 参数的小 transformer，单卡几分钟；
- 学生推理一次 ~1M FLOPs，比 4B 教师便宜约 3–4 个数量级；即使是 1.7B 学生，也比 4B 教师便宜 2–3 倍。

这就是本报告 Exp2 想验证的：**教师贵一次，学生便宜一辈子**。但前提是教师标签足够好、状态分布足够宽；否则学生会学到「只在教师轨迹上正确」的窄策略（我们的早期实验就踩了这个坑）。

## 4. 误差从哪里来

KIIS 的误差分解很有信息量[8]：

- JEV 单步「是否执行」错误率 7.0%；该判断正确时，状态变量错误率 0.0%。
- 也就是说，**错误几乎全部集中在「命令能不能执行」**，而不是「执行后变量变成什么」。
- 4 步 rollout 精确匹配 77.9%，零样本生成式 6.2%，persistence 15.6%。

这符合 JEV-as-a-Judge 的边界[15]：可从文本读出的判断（变量值）很准；需要推导的判断（前置条件是否满足、多步后果）会退化。世界模型恰恰两者都有，所以：

1. **把「是否执行」单独问**，不要和状态变量混在一个问题里（KIIS 实测混在一起会从 0.285 漂到 0.576）。
2. **给足前置条件**：状态文本里写清楚门锁、箱子开闭、手里有什么。
3. **短 horizon + 重规划**：每步从真实状态重新问，不要让 4 步误差一路滚下去。
4. **置信度升级**：低置信时调用强 LLM 或真实环境校验（REFLEX 的思路）。

## 5. 什么时候不该用 JEV

- **像素/连续控制**：JEV 没有图像编码器，也没有连续输出；Dreamer/DIAMOND/TD-MPC2 才是对的工具。
- **开放状态**：新物体、新关系、自由文本观测，选项枚举不过来；生成式 LLM 或 learned sim 更合适。
- **长时程组合推理**：需要多步反事实、数学、代码逻辑；JEV-as-a-Judge 明确说会落后[15]。
- **需要解释/审计**：JEV 不给理由，只给概率。
- **需要微调**：JEV 不开放权重，不能在自己的数据上继续训练；只能用 prompt/选项设计，或换 Kev/Tacit。

## 6. 决策矩阵（给工程选型）

| 场景 | 推荐 | 理由 |
|-|-|-|
| 文本 agent、状态可枚举、动作 ≤ 20、要求低延迟 | JEV choice / 世界模型前瞻 | 便宜、格式稳、概率可校准 |
| 动作集大、需要组合多步 | JEV 世界模型 + 规划器（beam/MCTS） | 单步 choice 不够，必须预测后果 |
| 需要部署到边缘/离线 | 蒸馏到 1M–1.7B 学生 | 教师只打标，学生常驻 |
| 像素/机器人/连续控制 | Dreamer/TD-MPC2/LeWAM/V-JEPA | JEV 没有观测模型 |
| 高风险、允许升级 | JEV + 强 LLM 级联 | REFLEX 的证据；置信度标边界 |
| 长时程、强推导 | 生成式 LLM / 形式化模型 | JEV 的已知短板 |
