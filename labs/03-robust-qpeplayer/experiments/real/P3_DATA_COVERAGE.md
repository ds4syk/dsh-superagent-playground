# P3 data coverage: exact limits (2026-11-28)

Scope: push the 3DMatch and KITTI real-data coverage as far as the session
budget allows and **document the exact limits**, without fabricating rows for
data that does not exist. Every number below is generated by
`threedmatch_low_overlap/run_low_overlap.py`, `kitti_more/run_kitti_more.py` or
read from `threedmatch_full/results/*.json`; the full round ledger
(hypothesis / change / command / before → after / keep / revert / artifact) is
[`../results/rounds_data.json`](../results/rounds_data.json) (45 rounds, 40
measured + 5 blocked).

## 1. 3DMatch: what "full" means

| claim | status | evidence |
|---|---|---|
| Official 3DMatch **geometric registration** benchmark = 8 scene sets | **full** | `threedmatch_full/results/manifest.json`: 8 sets, 433 fragments, 1623 `gt.log` pairs |
| All 8 sets downloaded and aggregated | **full** | `/mnt/storage1/syk/data/3dmatch_fragments/` (2.1 GB), manifest |
| "50 scenes" training split | **not usable for this benchmark** | the split ships RGB-D scans for descriptor training, not per-pair ground-truth transforms; no `gt.log`-equivalent GT exists to build oracle correspondences |

The 50-scene number is a **training** split for learned descriptors. The
registration benchmark with per-pair GT is the 8-set geometric benchmark, and
this protocol needs `gt.log` for every pair. We therefore keep the defensible
claim: **8 official sets / 1623 GT pairs is the full set for this protocol**.
No 50-scene success numbers were produced or invented (round R43).

### 1a. True low overlap is 0.20–0.50, not <0.20

Rescanning all 1623 pairs with the uncapped GT-NN estimator (2000 probes,
tau = 0.06 m) gives 608 pairs in [0.20, 0.50] and **zero** pairs below 0.20;
the per-scene minimum is 0.21–0.30. The release only lists pairs above roughly
30% nominal overlap, so a harsher band cannot be built from official data.

### 1b. "Low overlap" is geometric, not correspondence-quality

32 low-band pairs (4/scene) + 14 matched high controls (2/scene; hotel3 has none), 10 trials/cell:

| metric | 0.20–0.50 | >0.80 control |
|---|---|---|
| clean GT-NN base inlier | **0.953** (pair medians 0.881–0.995; 31/32 ≥0.90) | 0.984 |
| clean rotation / translation median | **0.47° / 0.016 m** | 0.19° / 0.005 m |
| GNC success p=0.7 | 1.00 | 1.00 |
| RANSAC-1000 success p=0.7 | 0.997 | 1.00 |
| IRLS-GM success p=0.7 | 0.92 | 0.99 |
| Kabsch p=0.3 / p=0.7 | 0.13 / 0.006 | 0.50 / 0.04 |

Because base matches are oracle GT-mapped nearest neighbours, every pair is
already inside the tau gate, so low geometric overlap cannot push the inlier
fraction below ~0.9. The measurable costs are (i) fewer correspondences —
3/32 pairs padded in ≥50% of clean trials, 5/32 at least once, up to overlap
0.266 — and (ii) a 2.5–3× worse clean pose floor. Any paper text must label
this band **geometric** low overlap, not a correspondence-quality stress test
(rounds R01–R19).

## 2. KITTI: 00–10 is covered only as "protocol frames"

| claim | status |
|---|---|
| All 11 odometry sequences 00–10 represented | **yes**, 32–33 protocol frames each (exact GT poses) |
| Full 00–10 Velodyne streams | **no** — official archive is 84.8 GB / 43,574 members, out of budget |
| Raw drives 0005/0009 fallback | **not needed**, not downloaded |

The protocol frames for 01/02/03/04/06/08/09/10 were range-fetched from the
HuggingFace mirror `sangramrout/velodyne` with one request per ZIP_STORED
member: 235 new frames / 465.7 MB / 67.5 s, CRC-checked. The per-sequence
mirrors (`yujie2696/kitti_odometry_NN`) were re-checked and contain images +
calib only, no `velodyne/`.

Robust table (10 trials/cell, imported protocol): GNC/RANSAC reach 1.00 at
p = 0.7 on all new sequences; pooled new-8 GNC 0.97 / 0.97 / 1.00 / 1.00 and
RANSAC 0.99 / 0.97 / 1.00 / 1.00 at p = 0 / 0.3 / 0.5 / 0.7; all-11 GNC
0.99 / 0.99 / 1.00 / 1.00. The only clean-cell dip is seq 08 (0.80 for GM,
0.90 RANSAC), traced to a 0.105–0.119 m translation near-miss on pair 0–1, not
a wrong basin. Correct wording: **"all 11 sequences are represented by the
33 frames the protocol uses"**, never "full 00–10 LiDAR" (rounds R20–R42).
