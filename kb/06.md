# 06 结论与建议：能不能用、怎么用、下一步

> **结论先行**：能用，但要把它放在正确的位置。**JEV 适合做「离散、可枚举、文本状态」的世界模型与快速动作判断层；不适合做像素/连续世界模型，也不适合独自承担长时程推导。** 最划算的落地方式是「JEV/强 LLM 当教师 → 小学习器当学生」：教师只在前端打标/兜底，学生常驻执行。

**如果只记三件事**：

1. **世界模型**：把下一状态拆成「是否执行 + 若干状态变量」的选择题，冻结 JEV 即可预测；误差集中在「是否执行」，不在变量值。
2. **动作生成**：直接 choice 最便宜；逐动作打分更稳；世界模型前瞻最贵但最像「用世界模型选动作」。动作集越大、越需要多步组合，越应该用前瞻/规划，而不是单次 choice。
3. **训练学习器**：用 JEV 给状态打动作标签，蒸馏到小模型；教师贵一次，学生便宜一辈子。标签必须覆盖学生实际会访问的状态（on-policy + off-policy/DAgger），否则学生会学成窄策略。

## 1. 直接回答用户的三个问题

### Q1：JEV 能不能当世界模型？

**能，但这是「因子化转移分类器」意义上的世界模型，不是生成式模拟器。**

- 需要你把状态拆成有限变量，并把每个变量的取值枚举成选项；
- 需要状态信息在文本里写清楚（门锁、箱子开闭、物品位置、手里有什么）；
- 需要转移规则相对简单、确定；越接近「读约束」而不是「算物理」，越可靠；
- 不能预测新物体、连续量、像素观测；这些要用 Dreamer/DIAMOND/TD-MPC2/LeWAM/V-JEPA。

KIIS 2026 在 TextWorld 上证明了这个做法可行（93.4% 闭环，4 步 77.9%），但作者自己限定：单任务、单 LLM、单 seed、评测同构、无独立复现。本报告 Exp1 用开放代理在自建世界上独立测了一遍，结果见 04。

### Q2：能不能让它输出「最合理的几个动作」，去训练学习器？

**能，但要分清「教师」和「学生」。**

- 教师侧：JEV 可以直接 choice（1 次/步）、逐动作打分（|A| 次/步）、或世界模型前瞻（|A|×Q 次/步）。三者的成本与效果不同，不能笼统说「JEV 会输出动作」。
- 学生侧：把教师在一批状态上的动作标签蒸进一个小策略；部署时只跑学生。
- 关键坑：如果只用教师自己走过的状态打标，学生会过拟合到窄分布；一旦偏离就崩。需要 on-policy + off-policy/DAgger 的状态聚合。

本报告 Exp2 做了这个对照；结果见 05。

### Q3：成本会低很多吗？

**会，但取决于你问多少问题、以及是否蒸馏。**

- 直接 choice + 学生部署：最低。教师只在打标时调用，学生推理成本可忽略。
- 世界模型前瞻：每步 |A|×Q 次决策，$0.01/回合量级；比生成式 LLM 便宜，但不是「几乎免费」。
- 生成式 LLM 当世界模型：每次要生成一段状态，延迟和费用都高一个量级；优点是开放状态。

**本报告 Exp1 的直接结果（Tacit-4B，500 条未见词表转移）**：一步精确匹配 **0.754**（persistence 0.745、Qwen3-4B typed 0.790、生成式 0.540），执行判断 0.696，变量宏平均 0.952；observe 0.981、simple 0.781、derive 0.709；4 步开环精确匹配降到 **0.18**。在真正执行的 182 条转移上，Tacit-4B 精确匹配 **0.566**，persistence 为 0。这说明：**它不是一个可靠的完整世界模型，但在「读状态、判执行、短程预测」上是有信息的**；长程必须重规划。

**本报告 Exp2 的直接结果（Tacit-4B，48 个测试世界，6 步）**：random 62.5%、choice 83.3%（4.5 次决策/回合）、score **100%**（9.8 次）、世界模型前瞻 83.3%（55.8 次）、oracle 100%。蒸馏：score 学生 **95.8%**（1M 参数，部署 0 次 JEV 调用）、oracle 学生 100%、WM 学生 83.3%。**逐动作打分比重型世界模型前瞻更准、便宜 5.7 倍**；世界模型前瞻没有跑赢简单打分，因为预测误差和手写效用函数抵消了它的信息优势。这个结果与「先问世界模型再规划一定更好」的直觉相反，值得在更大任务上复核。

## 2. 推荐架构（按场景）

### 2.1 文本 agent / 软件 agent / 回合制游戏

```
候选动作生成（规则/策略/LLM）
        ↓
JEV 打分：是否执行 / 是否推进目标 / 预测关键状态变量
        ↓
规划器（1–3 步前瞻 / beam）选动作
        ↓
低置信 → 强 LLM 或环境校验
        ↓
把 (state, action) 日志沉淀，离线蒸馏小策略
```

要点：

- 「是否执行」单独问，不要和状态变量混在一起；
- 选项要覆盖真值；动作集尽量 ≤ 20；
- 每步从真实状态重规划，不要长开环；
- 用置信度做升级，不要盲信概率。

### 2.2 部署到边缘/离线

- 教师（JEV/强 LLM）在训练期打标；
- 学生用 1M–1.7B 模型；输入最好是**角色化/结构化状态**（object role + state），而不是裸物体名；
- 用 DAgger 聚合学生访问到的状态；
- 上线前在同一 harness 上对比教师/学生闭环，不只看离线准确率。

### 2.3 像素/机器人/连续控制

不要用 JEV。用 DreamerV3 / TD-MPC2 / DIAMOND / LeWAM / V-JEPA 2 这类有观测模型或动作头的世界模型；JEV 最多做高层的离散决策/路由。

## 3. 工程检查清单

- [ ] 状态是否可枚举？每个变量的选项是否覆盖真值？
- [ ] 「是否执行」是否单独提问？
- [ ] 动作集多大？>20 时是否改用打分/前瞻？
- [ ] 每步是否从真实状态重规划？
- [ ] 是否有低置信升级路径？
- [ ] 蒸馏标签是否覆盖 on-policy + off-policy 状态？
- [ ] 学生输入是否角色化，避免记名字？
- [ ] 成本是否按「问题数 × 动作数 × 步数」算过？
- [ ] 是否在同一 harness 上对比过教师/学生/oracle/random？
- [ ] 是否标注了「论文声称 vs 独立复现」？

## 4. 本报告的边界

- 实验用的是开放代理（Tacit/Qwen），不是托管 JEV；托管 JEV 可能更强，也可能因版本漂移不同。
- 世界是确定性、完全可观测、小状态空间；真实环境有随机性、部分可观测、开放状态。
- Exp2 的测试世界与训练同词表（testsame），词表泛化由 Exp1 单独看；两者都没测新结构闭环。
- 只跑了一个 seed（预实验）；正式结论需要多 seed、多世界族、置信区间。
- 成本只算决策数与本地延迟，不含网络/重试/工程/标注成本。

## 5. 下一步（按性价比排序）

1. **在 KIIS 的 TextWorld harness 上做同构复现**：固定候选集与规划器，只换决策源（JEV / Kev / AnyJev / 微调小模型），补 k=8/16 与 replan 恢复。
2. **DAgger 式蒸馏**：2–3 轮「学生跑 → 教师打标 → 重训」，对比纯 BC；报告学生访问分布上的教师一致率。
3. **成本敏感性**：问题数、动作数、步数、API 价格（含补贴退出）四维网格；给出「JEV 何时仍划算」的边界。
4. **结构化学生**：把物体名替换为角色 token（container/key/food/door），验证词表泛化；再逐步放开到裸文本。
5. **托管 JEV 对照**：申请 API，重复 Exp1/Exp2 的关键单元格；固定 `jev-1.13.0`。
6. **长时程/随机环境**：加随机转移、部分可观测、k=8/16，测误差累积与重规划恢复。
