# 05 风险、审稿问题与执行清单

> **结论先行**：主表设计最大的风险不是“表不够多”，而是“表回答了错的问题”。审稿人真正会问的是：可认证性买到了什么、baseline 是否公平、设定是否透明、代价是否可接受。按 P0→P2 补三块——官方指标、SOTA 覆盖、证书/效率——就能把现有草稿从“完整案例”推到“可投稿主表”。

## 如果只记三件事

1. **先补三样**：绝对 `ET`(m) + `Epose`、5 个关键 baseline、tight/cert rate + 时间。这三样决定主表能不能立住。
2. **设定透明**：是否用 HIL 标签、是否 crop、是否在 val 上调参；写不清就会被当成“设定不公平”。
3. **只报 val 不算完成**：至少给一次官方 test/leaderboard 结果，或明确标注“val only”并说明原因。

## 3. 执行清单

### P0：让主表“可读”（约 1–2 周）

- [ ] 锁定 split 与预处理，写成一页协议（数据、resize、crop、HIL 标签、seed）。
- [ ] 把现有 4 个方法的结果重算成 `ET`(m)、`ER`(°)、`Epose`、失败率。
- [ ] 补 T1（双域 × 3 指标）与 T2（RMSE/max/失败率）。
- [ ] 补 T3 的 tight rate / cert rate / solver ms（先只测你的方法与 SPNv2）。
- [ ] 复现 KRN（或引用其同协议数字并标注）与 EPnP+LM、SQPnP 两个几何 floor。

### P1：让主表“可投”（约 2–3 周）

- [ ] 加 SDPRLayers（scalar/matrix）、EPro-PnP、PnP\*、Theseus 四个同层对手。
- [ ] 补 T4：local solver 替换、random init、no precision、first-stage、fallback。
- [ ] 补 T2 的 P90/P95/P99 与平移尾部（可放附录）。
- [ ] 跑官方 test/leaderboard，或写清“val only”的理由。
- [ ] 统一评测脚本，公开 split 文件与配置。

### P2：让主表“更强”（约 3–4 周）

- [ ] T5：像素噪声、外点、遮挡、距离、初始化 sweep。
- [ ] T6：SPEED 或 prisma25 跨域。
- [ ] 加 StructGCN / Wang 2022 / Wang 2023 中至少一个领域 SOTA。
- [ ] 证书随训练/噪声变化的图（借 2409 的 Fig 7 范式）。
- [ ] 失败样本可视化（flip、强反光、遮挡）。

## 4. 需要你拍板的四件事

1. **新方法定位**：A 层改进、B 新任务/新前端、还是 C 表征桥接？定位决定主表范式（见 00 页决策表）。
2. **是否使用 HIL 标签训练**：用，就是 transductive，叙事要改成“给定少量目标域标签”；不用，就与 SPNv2 的纯 synthetic 设定可比，但精度会掉。
3. **是否上官方 leaderboard**：上，需要提交与排队；不上，主表只能标“val only”，说服力打折。
4. **目标 venue**：T-RO/TAES 偏方法+应用，主表要方法型 + 应用展示；CVPR/ICCV 偏 SOTA 与消融，主表要应用型 + 强 baseline。两者表格顺序不同。

## 5. 检索方法与局限

- **做了什么**：arXiv 标题/摘要检索、OpenAlex `title_and_abstract.search`、Semantic Scholar 引用列表、DOI 元数据；逐篇读主表与实验节。
- **没做什么**：没有逐篇复现所有 baseline；没有穷尽 IEEE Xplore/Scopus 的灰色文献；没有检索中文文献。
- **结论的边界**：“未见 SDPR + spacecraft 的公开工作”是基于上述来源的检索结论，不等于绝对不存在；投稿前建议再做一次 Google Scholar/Scopus 复查。

## 6. 一句话行动建议

**如果只能做三件事**：补绝对 `ET` + `Epose` + 失败率（T1/T2）；补 5 个关键 baseline（EPnP+LM、SQPnP、SDPRLayers、EPro-PnP、PnP\*）；补 T3（tight/cert/time）。这三件做完，主表就从“案例展示”变成“可审稿的证据链”。
