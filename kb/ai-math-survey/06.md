# 06 结论与行动清单

> **结论先行**：AI 已经能批量产出“研究级数学草稿”，但还不能批量产出“可信定理”。当前最值得
> 投入的不是再换一个更大的模型，而是把**探索流水线**和**验证流水线**分开，并把验证工具
> （Lean/Comparator/领域计算）做成可复用的 Skill。

**如果只记三件事**：

1. **方案**：通用长思维链模型 + 工具 + Lean/Comparator 验证；没有单一模型端到端。
2. **工具**：探索阶段 Python 沙箱即可；可信交付必须客制化 Lean/自动形式化/审计。
3. **差距**：公开 benchmark 上 10–30 个百分点；研究级证明上更大，且“竞赛题饱和”不代表研究能力。

## 1. 四个问题的直接回答

### Q1：当前 AI 做科研/数学证明的主流方案是什么？

- **自然语言证明**：o1/o3/GPT-5、DeepSeek-R1/V3/V4、Kimi K1.5/K2/K3、Gemini、Claude。
- **形式化证明**：Lean 4 + Mathlib + RL/LLM（AlphaProof、DeepSeek-Prover-V2、Kimina、Goedel）。
- **智能体**：规划/子目标/工具/验证/修复（AlphaGeometry、COPRA、LeanCopilot、Aristotle）。
- **自动形式化/证明修复**：自然语言 → Lean，编译错误 → 修复。
- **工具增强**：CAS/数值/SAT/图搜索/区间算术。
- **人机协作**：AI 草稿 + 专家评审 + Lean + 独立复现。

### Q2：需不需要客制化工具/Skill？

- **探索**：不需要重工具；通用模型 + Python 沙箱 + 好的题面/评分即可。
- **可信交付**：需要。最小工具链是 Lean/Mathlib + Comparator + 自动形式化/证明修复 +
  领域工具 + 隔离编排 + 审计。
- **不建议**做一个“万能数学 Skill”；建议做“通用编排 + 领域工具包 + 验证流水线”。

### Q3：不同模型差距多大？

- 公开 benchmark：FrontierMath 2026-11 快照，GPT-5.5 Pro 52.4%、Kimi K2.6 38.97%、
  DeepSeek-V3.2 22.1%；IMO 2025 公开可测最高 31.55%（不到铜牌）。
- 研究级：OpenAI 内部模型能批量产出 722 篇手稿（平均 3 小时/结果），公开模型在有限预算下
  复现困难；本票实验见 05 页。
- 差距来源：长程规划、提出关键引理、识别死路、持续自审、工具使用、数据/算力。

### Q4：OpenAI 722 篇中的 10 个公开案例，DeepSeek/Kimi 能复现吗？

- “10 个公开案例”= 10 个公开推理摘要的 family（007, 017, 087, 102, 159, 197, 221, 271,
  287, 362）。
- 本票用 DeepSeek-V4-Pro 与 Kimi-K3 做信息隔离盲测；结果/失败模式见 05 页。
- **完整复现 0/10（DeepSeek-V4-Pro 与 Kimi-K3 都是）**；最高均分 2.5（DeepSeek 271/362），
  Kimi 最高 2.0（017/221）。没有案例达到“方向正确、主定理基本证出”的 4 分。
- 直接回答：**不能完整复现**；能给出有价值的部分结果/路线，但主定理未证，且部分输出把
  “已知定理/条件性证明”当成结果。差距主要在“提出关键引理 + 诚实自审”，不只是算力。

## 2. 行动清单（给团队）

### 近期（1–2 周）

1. **固化两条流水线**：
   - 探索：DeepSeek/Kimi + Python 沙箱 + 信息隔离 harness（复用 `repro/openai-10/`）。
   - 验证：Lean 项目 + `sorry`/公理扫描 + Comparator + 专家评审。
2. **做 3 个领域 Skill**：数论、组合、PDE/分析。每个包含：定义/引理、已知反例、数值脚本、
   Lean 模板、评审 rubric。
3. **建立研究级评测集**：不要只用 AIME/MATH-500；用未公开的开放问题/论文习题，人工评分，
   记录失败模式。

### 中期（1–3 月）

4. **自动形式化流水线**：题面 → Lean 命题 → 人工校对 → 冻结 → 证明搜索/修复。
5. **计算证书**：把数值/符号/SAT 的结果做成可复现证书（脚本 + 种子 + 环境 + 日志）。
6. **多窗口隔离**：不同模型/提示独立探索，交叉评审；避免互相污染。
7. **成本/延迟**：记录每个结果的 token/时间/工具调用；优化“何时停止”。

### 长期

8. **领域专用模型/RL**：如果要做 frontier，需要数学专项训练 + Lean 环境 + 大规模合成数据。
9. **社区验证**：与数学家合作，建立“AI 草稿 → 人类评审 → Lean”的流水线。
10. **安全/合规**：沙箱、无网络、权限最小化、敏感内容不外泄。

## 4. 下一步（建议）

- 把 10 个案例中已有 Lean 形式化的部分（017, 087, 197, 271, 287, 362）做一次**独立 Comparator
  检查**；需要安装 `comparator`/`landrun`/`lean4export`，并固定 Lean/Mathlib 版本。
