## 结论

1. **精度与可行性**：SCP 与 ALM 同档——p=16 上 SCP pen 中位 0.00 mm、rot 4.17°、trans 10.63 mm（ALM 0.00 mm / 4.17° / 10.63 mm），可行率 100% vs 100%。
2. **认证率**：主比较上 SCP 单起点 98% / 98% / 98%，ALM 100% / 100% / 100%。
   全部 6 个失败 trial 中 6 个的 SCP 初值就是无约束 cheirality 镜像解（depth_min<0、rot err≈180°），0 个是其它局部收敛/迭代上限。因此差距只在这类初值上出现，而不是普遍性差距。
   压力档（noise=0.020/bias=0.120，unc 镜像率 15%）上 SCP 认证 85%、ALM 认证 100% —— 镜像初值比例升高时 SCP 单起点的脆弱性被放大，这是**初值敏感性**，不是凸层不可行。
3. **速度**：SCP 单起点中位 130 / 135 / 142 ms vs ALM 218 / 239 / 232 ms（p=8,16,32）；SCP 约 90% 的墙钟花在 cvxpy/CLARABEL 的 SOCP 上、11% 在 restore 阶段。注意这只说明「本实现下 SCP 更快」，SCP 没有 ALM 那种与 p 无关的先验常数维复杂度论证。
4. **SCP + 重启**：主比较认证率 98% / 98% / 98% → 98% / 98% / 98%，本轮的失败没有被 2 个扰动初值救回（平均起点数 1.04）。这说明失败不是「随便扰动一下初值」能解决的局部收敛问题；ALM 的内层多起点是在 ALM 增广二次型上重解，机制不同。

**判定（keep / revert）**：keep `run_scp.py` 作为 B4 baseline。在这些合成实例上 SCP **可行、精度同档、中位更快**，是必须报告的强 baseline；ALM 的差异化不在本批次的认证率数值上，而在：(a) 对 cheirality 镜像初值的鲁棒性（高噪声档差异见表 1b/表 3）；(b) 运行时与 p 无关的先验常数维结构（SCP 需要 trust-region/restore 调参，且每次迭代解 SOCP）；(c) ALM 的证书/反向（FB、rank-deficiency）理论链与后验证书，而 SCP 的证书只验证「它恰好找到的那个点」。论文中必须同时报告 SCP 的收敛率/迭代数与认证率，不能只报 runtime 或只报精度。

## Caveats

- 本机 40 核多用户共享（测量时 load ~20–35），所有计时为单线程墙钟；绝对毫秒随负载漂移。SCP 与 ALM 在同一进程、同一实例上顺序测量，相对比较可用。
- SCP 用 cvxpy/CLARABEL 解 SOCP，ALM 用 scipy BFGS 多起点；两者实现栈不同，「更快」只对本实现成立（公平性说明见 protocol B4：算法层面对比）。
- 单起点 SCP 的初值 = 无约束 QPEP 解（与主表 soft/proj/ALM 完全相同的热启动），因此 SCP 在镜像初值上的失败继承自 unc 的镜像率，不是额外人为设置；本文件实测 unc 镜像率：主比较 2%，压力档 15%（主表 50-trial 高噪声档为 18%）。
- 只测前向 + 证书，不含反向（FB）与真实数据；合成实例的底面是平面，p≥16 后精度饱和，SCP 的精度优势/劣势在这类实例上不可分辨。
