# 08 附录：Jamba 澄清、限制与未验证清单

## A. 原消息写的是 Jamba，后来更正为 JEV

用户第一条消息写「最近很火的那个 Jamba（不是 ZEV）」，一分钟后又更正「打错了，这里是 jev」。本报告按 **JEV** 执行。这里说明如果确实指 **Jamba**，结论会怎样不同——两者不是一类东西。

| | Jamba（AI21） | JEV（TypeSafe） |
|-|-|-|
| 类型 | 混合 Mamba-Transformer MoE 大语言模型 | 决策模型（System One） |
| 输出 | 自回归生成文本 | 预枚举选项上的概率 |
| 代表工作 | Jamba 技术报告（arXiv 2403.19887）、Jamba-1.5（arXiv 2408.12570） | TypeSafe 发布博客、RLCD 训练 |
| 上下文 | 256k（Jamba），长上下文是卖点 | 每请求 64k、每问题 32k（可扩到 262k） |
| 当世界模型 | 可以，按「LLM 生成下一状态」的路线；格式脆弱、推理贵 | 可以，按「因子化状态的选择题」路线；便宜、格式稳、但只能枚举 |
| 输出动作 | 需要提示/微调成策略，动作是生成的 token | 直接对动作选项给概率，或对动作打分 |
| 成本 | 生成式，按输出 token 计费；长上下文 KV cache 大 | 输入 $0.042/MTok、输出免费；延迟 70–500ms |

**如果用户其实想要 Jamba**：

1. 它更适合「长上下文、开放文本、需要生成」的世界模型场景，例如长视频/长文档 agent 的状态摘要；
2. 它不能直接给出校准的动作概率；要当动作来源，需要 SFT/LoRA 成策略，或外接 value head；
3. 它的成本优势来自长上下文效率，不是「决策便宜」；在短回合、离散动作的场景，JEV 更合适；
4. 两者可以组合：Jamba 做开放状态/长上下文的世界模型，JEV 做快速离散决策层。

> 本报告的所有实验都是 JEV/其开源代理，不含 Jamba 实验。若需要 Jamba 路线的预实验，应另立 ticket。

## B. 限制清单

### B.1 实验层面

- 开放代理不是托管 JEV：Tacit-4B 是 AnyJev 自蒸馏模型，Qwen3-4B typed readout 是零样本读法；两者都不能代表 JEV 本体的全部能力。
- 单 seed、单世界族；没有置信区间；预实验结论只能当方向性证据。
- 世界确定性、完全可观测、状态空间小；真实环境有随机性、部分可观测、开放状态。
- Exp1 的测试世界与训练同结构、不同词表；没有测新结构闭环。
- Exp2 的测试世界与训练同词表（testsame），词表泛化由 Exp1 单独看；没有测新结构闭环。
- 动作集只有 9 类；真实机器人/游戏动作空间更大，结论不能直接外推。
- 生成式基线用 JSON 输出，解析失败按「状态不变」处理；不同解析规则会改变结果。

### B.2 文献层面

- KIIS 2026 是 2 页会议稿，会议 2026-11-26–28 才召开；无 proceedings/DOI、无独立复现。所有数字标注为「论文声称」。
- JEV 的架构（causal Transformer、MoE）来自黑盒逆向，不是官方确认；MoE 尤其未验证。
- TypeSafe 的价格/延迟是厂商口径，官方承认可能补贴；长期价格不确定。
- Genie 3 只有博客、无论文；常见规格（720p/24fps 等）本次未能从原文核验。
- IRIS 的 arXiv 编号是 2209.00588（不是 2209.03936）。
