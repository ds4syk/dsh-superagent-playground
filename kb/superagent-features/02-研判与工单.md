# 02 研判与工单：从一条消息到一张有授权的工作单

> **结论先行**：SuperAgent 用两层评估决定"要不要做"：确定性的 **Gate** 先判身份与强度，模型 **Assessment** 再判意图与方向。接受后生成一张 **Ticket**，其中 **Mandate** 记录这次授权的策略版本、范围、强度和命中的规则。工单通过**订阅**持续接收线程里的讨论，通过**输入**接收策略变更、CI 和人工消息。

**如果只记三件事**：

1. **Accept 不是"开工"，而是"授权"**：范围、强度、规则都写进 Mandate，执行器只能在这个范围内工作。
2. **工单不靠人再 @ 也能继续**：订阅把线程后续消息直接送到工单；人的消息由该工单的执行器判断归属，越界要交回。
3. **结束不等于失效**：已结束工单保留订阅，人的新消息可以按原 Mandate 恢复；被明确停止的工单除外。

## 0. 口径

| 概念 | 中文 | 说明 |
|-|-|-|
| Eval | 评估 | 对一批 Trigger 的判定，分 Gate 与 Assessment 两层；本身不持有状态 |
| Decision | 决定 | Eval 的结果：accept / stop / ignore / unavailable |
| Mandate | 授权 | Accept 授予的东西：策略版本、范围、强度、命中的规则、发送者身份与准入依据 |
| Ticket | 工单 | 一次授权工作的单位；拥有自己的状态、输入与订阅 |
| Assignment | 派工 | 把工单绑定到一个执行器实例；一张工单可以先后有多次 |
| Input | 输入 | 送到工单的上下文：扇出的消息、策略变更、恢复、文本备注 |

## 1. 第一层：Gate

Gate 是确定性的，按来源的 Policy 判定：

- **明确请求**：名单内的人 @ 代理或单聊；命中准入表"明确"格子。
- **推断候选**：名单外的人在有工单的线程里发言；准入表"推断"格子；来源 bot 名单里的 bot 的合规消息。
- **不准入**：其他 bot、被忽略的格子、`off` 模式下的推断。

Gate 还记录**准入依据**（`addressed` / `followup` / `admission` / `bot`）和接收范围，供工单恢复时重新验证。

## 2. 第二层：Assessment

只有候选才进入模型研判。主 Session 用三个只读工具完成：

| 工具 | 作用 |
|-|-|
| `orchestrator_eval` | 加载候选的有界上下文：线程、已有工单（含已结束）、触发批次 |
| `orchestrator_eval_read` | 按 id 读整条消息、线程前后页、图片、仓库文件；只读 |
| `orchestrator_eval_decide` | 提交结论：方向、每条规则的匹配判断、范围、理由、证据 |

**上下文窗口**：线程最早 5 条 + 触发前后各 5 条；长消息按字数截断并保留全长，其余消息先给摘要；需要时按 id 展开。飞书图片在窗口里以 `image_id` 列出，可按需读入。

**研判要建立三个独立事实**：

1. 讨论针对的是**这个仓库/项目**；
2. 参与者表达了**要实现某个具体改动**的意图；
3. 方向已经**足够确定**，可以在一个小的局部改动内完成。

缺一条就不能接。纯聊天、对别的产品的羡慕、没有落点的设计争论、只有含糊偏好，都只观察、不接单、不发确认。视觉类反馈还要额外满足"有明确目标或可验证的既有标准"。

**超时与失败**：研判有可配置时限（本实例 120 秒）；超时两次后第三次记 `unavailable`；模型或工具失败也记 `unavailable`，不冒充"规则不匹配"。面板只在 `unavailable` 仍是最新决定、24 小时内、且线程未排队时提示人；人可以"重新评估"或"忽略"。

## 3. Decision 与去重

| 结果 | 含义 |
|-|-|
| `accept` | 接单：创建工单、Mandate、Assignment、订阅与确认，通常在一个事务里完成 |
| `stop` | 人明确要求停止（只对人发起的停止；执行器不能替人宣布停止） |
| `attach` | 把一条消息挂到已有工单（开着的或已结束的），由该工单执行器当后续处理 |
| `ignore` | 普通讨论、重复、方向不明；记录理由，不打扰人 |
| `unavailable` | 研判没完成（超时、策略变化、工具失败），可重试 |

- **幂等**：同一条 Trigger 被接受两次只会有一张工单；接受以 trigger id 去重。
- **一个来源消息最多一张工单**；同一线程允许多张独立工单，评估会参考线程上已有工单（含已结束）避免重复。
- **attach 只在消息明确指向工单时使用**：引用/链接了该工单的 PR、Issue、源消息或确认，或明确指向"刚做的那个改动"且只有一个工单吻合。主题相似不算；attach 会把工单订阅到整个线程，挂错代价高。
- **handback 的候选**：执行器把越界请求交回后会带原因重新出现，主 Session 可以接单、挂到别处或忽略，但不能挂回原工单。

## 4. 工单的阶段

工单只定义自己的状态，不跟随执行器 Session：

| 阶段 | 条件 | 面板标签 |
|-|-|-|
| person / delivery | 输入投递失败，按 2 秒起、翻倍至 1 分钟重试 | 输入未送达 |
| person / answer | 存在待人工决定的问题 | 待回答 |
| person / review | 最新报告是 `ready` | 待审阅 |
| person / blocked / failed | 最新报告是 `blocked` 或 `failed`，且之后没有人发消息 | 阻塞 · 失败 |
| working / queued | 没有 Assignment，或 Assignment 待启动 | 排队 |
| idle | 最新报告是 `waiting`，或 Assignment 已结束 | 等待触发 |
| working | 其他情况 | 工作中 |

`person` 阶段表示"没有人的输入就无法继续"；人的新消息会把 `blocked`/`failed` 工单释放回执行器。

## 5. 订阅：让讨论自动到达

- 接受工单时订阅它的每个触发线程；绑定 PR 时订阅 PR 线程。
- 订阅线程上的**每条**后续消息（任何人、任何 bot、CI）都会扇出到订阅工单，作为上下文；这**不需要 @，也不给新授权**。
- 人发在工单自己线程上的消息，不进入新一轮 Eval：由该工单的执行器判断是否属于本工单。属于就处理并确认；超出范围就 `orchestrator_trigger_handback` 交回，由主 Session 重新路由；与本工单无关的附加线程可以 `orchestrator_thread_unrelated` 退出，且不在那里回复。
- **上下文订阅**（`orchestrator_thread_follow`）：只送上下文，不给后续强度、不恢复已结束工单。
- **恢复**：已结束工单保留订阅；人的消息可以在原 Mandate 下恢复，先做重新验证（来源仍监听、名单仍成立、推断类还需要 `auto` 模式与规则仍启用）。bot/CI 不唤醒已结束工单。
- **停止**：人明确 stop 会撤销 Mandate，工单保持结束并拒绝后续消息；要在那里继续工作，必须重新接单。
- **退订**：人可以丢掉线程上的全部订阅；执行器只能退掉自己工单对附加线程的订阅。
- **工单结束时**：没读过、没确认、没回答、没交回的消息回到 Eval（前提是没有别的工单仍拥有它）。

## 6. 输入与审计

- 输入包括：扇出的 Trigger、策略变更通知、恢复、主 Session 的文本备注（≤100 词）、CI/review 反馈。
- 执行器把消息取进 Session 历史才算"已读"；一次被取消或异常中断、未进入历史的步骤不算已读。
- 每张工单都保留：来源 Trigger、Decision 与理由、范围与策略版本、订阅、Assignment、报告与问题、投递失败记录。
- 每条 Trigger 的**去向**（被来源过滤、被研判、扇出到哪些工单、被哪个工单交回、被谁确认/回答）都可查，面板的 Trigger 页与丢弃消息审计使用同一份记录。

## 7. 工单怎样结束

| 结果 | 触发条件 |
|-|-|
| `completed` | 报告 `ready`，且不跟随任何 PR/线程 |
| `dropped` | 执行器判断没有人需要行动（不复现、已被取代、无需处理），不发消息 |
| `merged` / `closed` | 跟随的 PR（们）全部关闭，按最近一次关闭的结果结束 |
| `stopped` | 人明确停止 |

启动或 prepare 失败不是一种"结束结果"，而是工单先停在 `failed` 阶段等人处理；重试或人的消息解除后继续。

- 工单跟随它打开的 PR，也跟随从它分支打开的 PR；PR 合并/关闭会结束工单并保留订阅，聊天频道收到一次结果通知。
- 关闭不会结束仍有未完成恢复/重试工作的工单；执行器确认过但尚未产出新报告的跟进也会让它多等一轮。
- "待审阅"的准确含义是：**有 `ready` 报告且有 PR**，不是 PR 存在本身。
