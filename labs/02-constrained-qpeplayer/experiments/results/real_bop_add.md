`poses.npz` that exactly replays the published `raw.json` trials.

Metric: BOP ADD / ADD-S on `models_eval` meshes; **ADD(-S)** uses ADD for
asymmetric objects and ADD-S for the symmetric ones (LM/LM-O obj 8 eggbox,
obj 9 glue; none of the YCB-V objects here is symmetric). Units: mm.

the published BOP table (verified row-for-row below).

## Constraints trade accuracy for admissibility (does not improve ADD)

- **LINEMOD**: ALM ADD(-S) median 35.4 mm vs unconstrained 31.5 mm vs projection 28.1 mm; penetration 11.3 -> 0.0 mm; feasible 13.3% -> 100.0%. So the constrained solve buys admissibility (zero penetration, 100% feasible) and pays for it in ADD under this deliberately biased correspondence layer -- ALM is **not** an ADD winner here.
- **LM-O**: ALM ADD(-S) median 25.4 mm vs unconstrained 22.1 mm vs projection 18.1 mm; penetration 14.9 -> 0.0 mm; feasible 6.9% -> 100.0%. So the constrained solve buys admissibility (zero penetration, 100% feasible) and pays for it in ADD under this deliberately biased correspondence layer -- ALM is **not** an ADD winner here.
- **YCB-Video**: ALM ADD(-S) median 25.2 mm vs unconstrained 17.3 mm vs projection 8.9 mm; penetration 14.1 -> 0.0 mm; feasible 6.0% -> 100.0%. So the constrained solve buys admissibility (zero penetration, 100% feasible) and pays for it in ADD under this deliberately biased correspondence layer -- ALM is **not** an ADD winner here.


## Reading the numbers

- ADD/ADD-S are *pose* errors on real meshes and real GT poses, but the
  correspondence layer is synthetic-by-projection, so they must be read as
  "error of the constrained solve on a 1 px-noisy real-object instance",
  not as a BOP leaderboard entry.
- The downward pixel bias (10/20/30 px) is what manufactures penetration in
  the unconstrained solve; ADD grows with it, and that is the quantity the
  constrained methods trade against penetration.
