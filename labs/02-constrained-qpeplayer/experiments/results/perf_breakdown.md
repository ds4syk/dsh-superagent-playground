## 结论（本文件内可核对）

1. **SDP 是否主导：否（冷缓存时约占 ALM 的 21%–28%）**。SDP base 中位 42.4 ms（p=8）→ 60.4 ms（p=64），ALM 中位 231.4 → 219.2 ms；pipeline 中 SDP 占比 11.1%–15.0%。固定 p 的证书编译一次后可复用：参数化 warm solve 只需 1.4–1.8 ms（比 cold 快 26–33×），因此「证书成本」在流式场景可按 p 摊销为几毫秒。

2. **ALM 总时长的 p 斜率接近 0，但单项各有标度**：ALM 总 -0.033（R²=0.56，说明 p 的效应小于 trial 间噪声），其中装配 +0.316（接近 O(p)，R²=0.96）、内层 -0.037（近似常数，与 p 无关的 10×10/3×10/3×3 维一致）、SDP base +0.172、SDP base+RLT +1.520。装配虽然按 p 增长，基数很小——p=8 时也只占 ALM 的 0.6%，p=64 时 1.3%。

3. **ALM 的时间主要在反复的内层多起点 BFGS**（占 98%–99%；外层中位 12.8 次、solve_inner 16.2 次、scipy BFGS 97.5 次），而不是装配或 p 相关的项；因此加速 ALM 的方向是减少外层/内层重解次数（热启动、活跃集预测），而不是优化 10×10 装配。注意外层活跃集一致性在 p=64 上触发 fallback 的 trial 占 30%（其它 p 均为 0%），但每次 fallback 只花 ~1.7 ms，所以耗时的方差主要来自内层起点/迭代次数而不是 fallback。

4. **RLT 的 p 标度明显更差（约二次）**：SDP base 从 p=8 的 42.4 ms 到 p=64 的 60.4 ms（1.4×），而 base+RLT 从 63.6 ms 到 1556.9 ms（24.5×），log–log 斜率 +1.52 vs base +0.17；RLT/base 的耗时比从 1.5× 升到 25.8×。因此 RLT 只能作为可选/难题档的紧性消融，默认证书用 base。

## Caveats

- 本机 40 核、多用户共享（测量时 load ~20–35），所有计时为单线程墙钟；绝对毫秒数会随负载漂移，且与 `run_main.py`（默认多线程）的主表毫秒不可逐位比较。本文件的可靠结论是**同一进程内的相对占比与 p 斜率**。
- 内层是 6 起点 BFGS 的数值全局替代，不是 QPEP 的 Gröbner 枚举；换真实枚举后内层/外层的绝对占比会变，但常数维装配 O(p) 的结论不变。
- 证书缓存测试假设同一 p 下 Shor SDP 结构固定、只有 Qh 与 p 条约束系数变化（本实验成立）；参数化 warm solve 的数值与冷解最大差 1.2e-09，tight 最大 9.2e-10，仍满足 1e-6 的证书阈值。若实例差异极大（不同 p / 不同约束类型），warm start 的收敛性需另行验证。
- 本文件只测前向/证书，不含反向（FB）与真实数据；p=8..64 的精度饱和是结构性的（底面为平面，≥3 不共线接触点已等价于整面非穿透），见主表说明。
